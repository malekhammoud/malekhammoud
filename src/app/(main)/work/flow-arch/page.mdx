## The problem

Every focus tool I'd used was a thing running *inside* the environment it was
supposed to be protecting you from. A browser extension that blocks a site is
one keystroke from being disabled, because it lives at the same level as the
thing it's fighting.

The version that actually works has to sit lower down — in the compositor, the
session manager and the network layer, where the decision has already been made
by the time an application gets a say.

## The constraint

Building an OS distribution has a constraint that most side projects don't:
**strangers install it on their own machines.** That changes the standard
completely.

- It has to install cleanly on hardware I have never seen.
- A crash isn't an inconvenience, it's someone's desktop.
- Every custom component has to survive a system update that I don't control.
- It needs documentation good enough that nobody has to ask me anything.

Arch as a base makes the first and third of those harder — it's a rolling
release, so the ground moves — and makes everything else possible, because
nothing is hidden.

## What I built

**The desktop** is Hyprland, a Wayland compositor, configured from scratch
rather than themed: keybindings, window rules, idle behaviour, lock screen and
power handling all specified deliberately.

**The session tooling** is where the actual idea lives. Enforced Pomodoro
cycles, intention prompts that ask what you're about to do before letting you
start, and check-ins during a session. These are QML surfaces driven by Python
daemons, sitting at the session level rather than inside an application — so
they aren't something you can alt-tab away from.

**The theming system** generates a coordinated set of assets across the
compositor, the bar and the applications from a single theme selection, so
switching looks like a design decision instead of a config-editing afternoon.

**Packaging and documentation** — the unglamorous half, and the half that
decides whether anyone but you ever runs it.

## The outcome

Public release, **500+ installs**, and enough documentation that support
requests are rare rather than constant.

The thing I actually learned from it has nothing to do with Linux. Enforcement
only works when it lives below the thing being enforced. A guard rail at the
same level as the behaviour is a suggestion. That principle is exactly why, when
I build an agent now, permissions are scoped at the credential rather than in
the prompt — a model asked nicely not to do something is a browser extension.

## Why it's on this page

It's the closest thing I have to a proof of the boring claims: that I can
package something, document it, and hand it to people who will never speak to
me, and have it keep working. Most of what I do for clients ends the same way —
the measure of the handover is that nobody needs to call.
